# 真机回归清单

> 用途：模拟器无法覆盖的设备侧行为，统一在这里按功能域列成可勾选项。
> 每条包含「操作 → 预期」，并注明依据的修复/文档，避免回归时凭印象判断。
> 执行后把结果写回对应模块文档的「验证记录」一节，不要只勾选。

## 0. 执行前提

| 项 | 要求 |
| --- | --- |
| 设备 | HarmonyOS 6.0.2(22) 及以上真机（模拟器不能验证通知响铃、代理提醒配额、卡片桌面渲染） |
| 包 | 已签名 release 或已配置 p7b 的 uat 包（`unsigned` 包在真机装不上） |
| 账号 | 至少 1 个已登录米游社账号，且原神 / 星铁 / 绝区零中至少 2 个游戏有角色 |
| 通知 | 系统设置里允许本应用通知，且允许「锁屏 / 横幅 / 响铃」 |
| 日志 | `hdc shell hilog -x \| grep -E "StaminaNotificationService\|WIDGET"` 另开一个窗口 |

## 1. 通知（最高优先级）

> 依据：`features/notification/src/main/ets/model/service/StaminaNotificationService.ets`、
> [`notification-service-modules-analysis.md`](./notification-service-modules-analysis.md) M1。

- [ ] **M1 提醒时间不后移**：让某个游戏体力低于阈值（例如阈值 200、当前 180），进入首页触发同步，记下日志里的 `delay=NNNNs`。反复切到其他 Tab 再回首页 3 次。
      预期：`delay` 只随真实体力恢复时间递减，不因为进首页而重新变大；日志出现复用分支，而不是每轮都 `publishTimerReminder`。
- [ ] **M1 阈值变更后重建**：把该游戏阈值改小，再进首页。
      预期：旧提醒被取消，按新阈值重新发布一条，`delay` 相应变小。
- [ ] **M1 卡片删除后不重复计数**：在桌面删掉一张卡片，回到 App 触发同步。
      预期：配额计数下降，日志出现 `was removed, cleaning config`，不再出现 `The ID of the form to be operated does not exist`。
- [ ] **定时提醒真实到达**：把阈值设成「当前体力 + 少量」，锁屏等待。
      预期：到点系统通知弹出，锁屏 / 横幅 / 响铃按系统设置生效；点击通知能打开 App 且不跳到错误包名。
- [ ] **App 被杀后仍生效**：设置提醒后从最近任务划掉 App，等待到点。
      预期：通知仍然到达（这是代理提醒的核心价值）。
- [ ] **即时通知去重**：体力已满且已通知过，反复进首页。
      预期：不再重复推送同一游戏的即时通知（日志 `skip immediate notification (already notified at threshold N)`）。
- [ ] **STYLE_B 合并通知**：切到样式 B，让 2~3 个游戏同时达标。
      预期：合并为一条通知，展开后最多 3 行；样式切换后旧样式通知不残留。
- [ ] **配额上限**：构造超过 30 条提醒的场景（多账号 / 多角色）。
      预期：第 31 条被拒绝并弹出上限提示对话框，而不是静默失败。
- [ ] **关闭单游戏后撤回**：某游戏已有定时提醒，关闭它的开关。
      预期：该游戏的提醒从系统提醒列表消失（当前已知缺口：关闭总开关/单游戏后已发布的**即时**通知不撤回，见通知文档 L4）。

## 2. Widget 卡片

> 依据：[`widget-subsystem-modules-analysis.md`](./widget-subsystem-modules-analysis.md) H3 与本次 `16501001` 修复。

- [ ] **六尺寸添加**：1×2（原神 / 星铁 / 绝区零）、2×2、2×4、4×4 逐个添加到桌面。
      预期：全部渲染成功，无空白卡片；`form_config.json` 里 6 个 `name` 都能在卡片选择器看到。
- [ ] **新鲜度角标**：数据同步后立即查看卡片，再放置 1 小时以上（或改系统时间）后查看。
      预期：1 小时内显示「刚刚同步」类文案；超过 1 小时显示陈旧高亮，且时间文案随 `updatedAt` 变化。
- [ ] **空态**：删除所有账号后查看卡片。
      预期：显示引导态而不是崩溃或空白。
- [ ] **派遣头像**：原神有派遣任务时，1×2 / 2×2 显示派遣头像。
      预期：头像与游戏内一致，无错位。
- [ ] **删除卡片后清理**：反复添加 / 删除卡片 5 次，每次删除后触发一次同步。
      预期：`widget_configs` 不累积；日志 `removed=N` 递增，`failed=0`。
- [x] **卡片点击**（2026-11-19 模拟器已验证）：点击 4×4 卡片任意区域。
      预期：打开 App。1×2 卡片直达对应游戏便笺详情页（已实现）；2×2 / 2×4 / 4×4 进首页。
- [ ] **1×2 卡片直达**：分别添加原神 / 星铁 / 绝区零 1×2 卡片并点击。
      预期：进入对应游戏的便笺详情页，账号与角色正确；App 未启动和已在后台两种状态都要验证。
- [x] **绝区零体力显示**（2026-11-19 模拟器已验证）：绝区零卡片显示 `当前/240` 与恢复时间，不应出现 `0/160 已回满`。
      背景：Widget 接口降级同步曾清空 `raw_json`，已修数据层并在解析层回退 `widget_raw_json`。

## 3. 启动与 Ability

> 依据：[`ability-and-startup-modules-analysis.md`](./ability-and-startup-modules-analysis.md)。

- [ ] **冷启动**：杀进程后启动。
      预期：直达首页（已登录）或登录页（未登录），无白屏。
- [ ] **初始化失败可见**（M1）：断网 + 清缓存后启动。
      预期：至少给出一条用户可见提示，而不是只写日志后停在空首页。
- [ ] **`loadContent` 失败兜底**（M3）：暂无法人为触发，回归时观察白屏。
      预期：若出现白屏，说明该项未修复，需补重试或错误页。
- [ ] **从外部 Want 进入**：通过通知 / 卡片 / 分享链接进入。
      预期：落在正确页面，不出现重复实例。

## 4. 首页与列表

- [ ] **次要数据刷新**：首页下拉刷新，观察次要指标（洞天财富 / 每日委托 / 模拟宇宙积分等）是否更新。
- [ ] **M6 列表滚动与折叠**：3 个游戏卡片全部展开，长距离滚动。
      预期：不卡顿、不闪烁，折叠状态保持。
- [ ] **人机验证**：触发米游社验证码场景。
      预期：WebView 正常加载并可完成验证（GAP 相关项）。
- [ ] **多语言**：切换系统语言为英文 / 繁体。
      预期：首页、通知、Widget 无中文硬编码残留（GAP-10）。

## 5. 角色与详情

- [ ] **角色列表 → 详情**：三个游戏各进一次详情页。
      预期：属性 / 技能 / 武器 / 面板完整，返回后列表位置不丢。
- [ ] **详情页材料计算入口**：点「材料计算」。
      预期：进入只读材料计算页，返回后详情页数据刷新正常。
- [ ] **GAP-13 材料清单关联角色**：在材料清单里点角色。
      预期：能跳转到对应角色详情（当前未接通，`MaterialListContentView.ets:67`）。

## 6. 工具 / 材料计算

- [ ] **材料计算只读展示**：从角色详情进入，检查目标等级 / 技能等级展示。
      预期：与角色当前状态一致，不可误编辑。
- [ ] **返回刷新**：修改角色等级后返回材料计算。
      预期：数据同步更新。

## 7. 我的 / 外观 / 隐私

- [ ] **主题切换**：深色 / 浅色 / 跟随系统三态切换。
      预期：立即生效，重启后保持；卡片与页面无残留深色背景。
- [ ] **隐私协议页**：首次启动与新版本更新后各触发一次。
      预期：内容可滚动，同意后不再重复弹出。
- [ ] **账号详情**：进入账号详情，检查多角色展示与解绑。
      预期：解绑后首页与通知配额同步更新。

## 8. 折叠屏与多窗口

- [ ] **展开 / 折叠切换**：在折叠屏上反复切换形态。
      预期：布局自适应，无内容裁切，窗口监听不泄漏（Ability L1）。
- [ ] **分屏 / 悬浮窗**：与其他应用分屏。
      预期：列表与卡片正常，无重叠。

## 9. 网络异常

- [ ] **断网启动**：飞行模式下启动。
      预期：显示可重试的错误态，恢复网络后重试成功。
- [ ] **弱网同步**：限速下触发同步。
      预期：不重复发布提醒，不产生孤儿提醒（依赖 `CoalescingRunner`）。
