## 文档版本：V1.0

## 一、项目概述

1. 项目名称
   米游社数据工具箱（纯血鸿蒙版）
2. 产品定位
   本应用为 纯血鸿蒙原生工具类应用，基于 HarmonyOS NEXT 5.0+（API 11 及以上）开发，无安卓兼容层，专注为米哈游旗下游戏用户提供「多账号、多游戏」个人数据查询与可视化展示服务。
   核心价值：本地优先存储，保障用户数据安全；多账号同时展示，提升查询效率；纯鸿蒙原生体验，适配全设备形态；界面对标 enka.network，呈现专业、清晰的角色与战绩数据，满足玩家对游戏数据管理的核心需求。
3. 目标用户
   明确为米哈游旗下游戏（原神、崩坏：星穹铁道、绝区零）玩家，核心用户特征：拥有 1 个及以上米游社账号，需要便捷查看多个账号的角色练度、游戏战绩，使用鸿蒙设备（手机、折叠屏、三折屏、平板、鸿蒙 PC），注重数据安全与操作便捷性。
4. 适配范围
   - 设备适配：手机、折叠屏、三折屏、平板、鸿蒙 PC，支持横屏、竖屏、折叠 / 展开状态自适应布局，无显示异常
   - 系统适配：严格适配 HarmonyOS NEXT 5.0 及以上版本，不兼容低于该版本的鸿蒙系统
   - 语言适配：支持 3 种语言（简体中文、繁体中文、英文），支持手动切换，切换后实时生效，无需重启应用
   - 主题适配：支持 3 种主题模式（浅色模式、深色模式、跟随系统），支持手动切换，全局实时生效
   - 游戏适配：支持原神、崩坏：星穹铁道、绝区零，后续可扩展其他米哈游旗下游戏

## 二、核心业务规则

## 2.1多账号管理核心规则（明确边界，无歧义）

1.  账号数量：支持添加多个米游社账号，无上限限制（仅受设备存储容量约束）
2.  数据隔离：所有账号数据完全独立，互不干扰，不会出现账号间数据串扰、混淆的情况
3.  展示规则：
    - 首页战绩总览：所有已添加账号按「账号分组」展示，每组展示该账号下所有游戏的核心战绩数据
    - 角色列表 / 详情页：仅展示「当前选中账号」的数据，支持通过页面右上角按钮切换账号或刷新数据
4.  账号操作：支持账号添加、删除、切换、登出，支持清除单个账号的本地数据（不影响其他账号）
5.  登录态管理：账号登录态本地持久化存储，有效期内自动复用，登录态过期时，引导用户重新登录

## 2.2登录功能需求

1. 登录方式（3 种，可任选其一，无优先级限制）
   - 米游社扫码登录：应用内展示米游社登录二维码，用户使用米游社 App 扫码授权，授权成功后自动完成登录，获取登录凭证
   - 应用内网页授权登录：应用内嵌入米游社官方登录网页，用户输入米游社账号密码（或验证码）登录，登录成功后自动提取登录凭证，无需用户手动复制
   - 手动粘贴凭证登录（备用方案）：用户手动复制米游社登录凭证（Cookie），粘贴至应用指定输入框，验证通过后完成登录

2. 安全约束
   - 所有登录凭证（Cookie）仅在本地加密存储，不上传至任何第三方服务器、不进行云端同步
   - 不记录用户米游社账号密码，仅存储登录凭证，保障用户账号安全
   - 登录过程中，若触发米游社风控验证，需用户手动完成验证后，方可继续登录流程

3. 游戏数据展示需求

4. 支持游戏范围
   明确支持 3 款游戏，后续可扩展：
   - 原神
   - 崩坏：星穹铁道
   - 绝区零

## 2.3.2 首页战绩总览（核心展示页面，逻辑闭环）

1. 布局规则：采用「List+Group」分组布局，按账号维度拆分，每组为一个账号，组内展示该账号下所有游戏的战绩卡片
2. 展示内容（每个游戏战绩卡片必含）：
   - 基础信息：游戏名称、游戏内账号昵称、游戏内 UID、服务器
   - 实时数据：当前体力 / 开拓力 / 活力数值、体力完全恢复剩余时间（精确到分钟）
   - 任务进度：每日委托完成状态（已完成 / 未完成）、周本剩余挑战次数
   - 核心战绩：原神深渊通关进度、星穹铁道忘却之庭通关进度、绝区零相关战绩
3. 交互规则：点击账号分组标题，可展开 / 收起该账号下所有游戏的战绩卡片；点击某款游戏的战绩卡片，可跳转至该游戏的角色列表页

## 2.3.3 角色列表页（边界清晰，操作明确）

1. 展示范围：仅展示「当前选中账号」下的所有角色，不展示其他账号角色
2. 筛选功能：支持按 3 种条件筛选角色，筛选条件可组合使用：
   - 游戏筛选：按原神、星穹铁道、绝区零筛选
   - 星级筛选：按角色星级（1-5 星）筛选
   - 属性筛选：按角色元素属性（原神）、属性类型（星穹铁道）筛选
3. 展示内容（每个角色列表项必含）：
   - 基础信息：角色头像、角色名称、角色星级、角色等级
   - 核心装备：武器 / 光锥名称、精炼 / 叠影等级（简要展示）
   - 额外信息：角色命座 / 星魂数量（简要展示）
4. 交互规则：点击角色列表项，跳转至该角色的详情页；页面右上角提供「切换账号」「刷新数据」两个按钮，点击可执行对应操作

## 2.3.4 角色详情页（细节完整，对标 enka.network，无模糊表述）

1. 展示内容：
   - 基础信息模块：角色头像、角色名称、角色等级、命座 / 星魂数量、好感度（羁绊）、元素属性（原神）/ 属性类型（星穹铁道）
   - 武器 / 光锥模块：武器 / 光锥名称、等级、精炼 / 叠影等级、副词条（完整展示所有副词条及数值）
   - 圣遗物 / 遗器模块：套装名称、套装效果（已激活 / 未激活）、单件圣遗物 / 遗器（花 / 羽 / 沙 / 杯 / 头）的主属性、副属性及数值
   - 天赋 / 行迹模块：天赋 / 行迹名称、等级（完整展示所有天赋 / 行迹）
   - 属性面板模块：角色完整属性面板（攻击力、防御力、生命值、元素精通等所有核心属性，数值精确到个位数）
2. 交互规则：支持上下滑动查看所有模块；支持截图分享当前角色详情页（后续 V2.0 扩展功能）

## 2.4 数据更新与缓存规则（逻辑明确，适配两款工具识别）

1. 首次加载规则：应用首次打开（或新增账号后首次查看），自动发起网络请求，获取最新游戏数据，解析后存入本地存储，完成后展示数据
2. 二次加载规则：后续打开应用（或切换账号），优先读取本地已存储的数据，实现页面秒开，提升用户体验
3. 手动刷新规则：用户可通过「下拉刷新」（首页、角色列表页）或「刷新按钮」（角色详情页），重新发起网络请求，获取最新数据，更新本地存储并刷新界面
4. 缓存约束：本地缓存数据长期保留，仅在用户手动清理缓存、删除账号或刷新数据时更新，不自动清理

## 2.5 人机验证需求（触发条件、操作流程明确，无歧义）

### 2.5.1 触发场景（明确两种核心场景）

1. 登录场景：用户使用扫码、网页授权、手动粘贴凭证登录时，米游社返回风控验证请求
2. 数据刷新场景：用户手动刷新数据时，米游社返回风控验证请求

### 2.5.2 实现规则

1. 验证方式：弹出验证弹窗，弹窗内嵌入极验 Geetest v4 验证网页（无需自定义验证 UI）
2. 操作流程：用户手动完成验证（滑块、点选等验证类型）→ 验证通过后，应用获取验证参数 → 继续执行原操作（登录 / 数据刷新）
3. 约束规则：不支持自动验证，所有验证操作必须由用户手动完成；验证失败时，提示用户重新验证，可选择取消验证（取消后终止原操作）

## 2.6 调试模式（Mock 模式）需求（边界清晰，适配两款工具识别）

1. 模式切换：支持「Mock 模式」与「Release 模式」手动切换，切换后实时生效，无需重启应用
2. Mock 模式规则：
   - 不发起任何真实网络请求，不与米游社接口交互
   - 所有展示数据均来自本地预设的 Mock JSON 文件，数据格式与真实数据完全一致
   - 数据展示逻辑、界面交互与 Release 模式完全相同，仅数据源不同
3. Release 模式规则：
   - 正常发起网络请求，与米游社接口交互，获取真实游戏数据
   - 数据处理、存储、展示逻辑与 Mock 模式完全共用
4. 核心目的：Mock 模式用于应用功能调试、界面开发，无需依赖真实接口；Release 模式用于用户正常使用，获取真实数据

## 2.7 设置功能需求（模块清晰，操作明确）

### 2.7.1 语言设置

- 支持语言：简体中文、繁体中文、英文
- 操作规则：手动切换语言，切换后全局实时生效，无需重启应用；默认语言为简体中文

### 2.7.2 主题设置

- 支持模式：浅色模式、深色模式、跟随系统
- 操作规则：手动切换主题，切换后全局实时生效，无需重启应用；默认模式为跟随系统

### 2.7.3 缓存管理

- 操作功能：支持手动清理本地缓存（包括图片缓存、数据缓存），清理后释放设备存储空间
- 反馈规则：清理完成后，提示用户 “缓存清理成功”，并显示释放的存储空间大小

### 2.7.4 账号管理

操作功能：新增账号、切换账号、删除账号、登出当前账号、清除单个账号本地数据
约束规则：删除账号时，弹出确认弹窗（提示 “删除后该账号所有本地数据将被清除，不可恢复”），用户确认后执行删除操作

## 三、非功能需求

### 3.1 安全需求（核心约束，无模糊表述）

1. 数据安全：用户登录凭证、游戏数据、账号信息仅在本地加密存储，不上传至任何第三方服务器、不进行云端同步，不泄露用户隐私
2. 权限需求：仅申请必要权限（网络权限、存储权限、相机权限（用于扫码登录）、通知权限（后续 V2.0 提醒功能）），不申请无关权限，权限申请时明确告知用户权限用途
3. 风控约束：严格遵循米游社接口使用规范，控制请求频率，不破解接口、不恶意爬取数据，仅用于用户个人数据查询，避免触发米游社账号风控

### 3.2 性能需求

1. 启动性能：冷启动时间≤2 秒，热启动时间≤1 秒
2. 流畅度：页面滑动、切换无卡顿，帧率稳定在 60fps 以上，无掉帧、闪退现象
3. 响应速度：数据加载响应时间≤1 秒（网络良好情况下）；数据库读取响应时间≤100ms
4. 弱网适配：弱网环境下，优先展示本地缓存数据，不出现页面空白、加载失败的情况；网络恢复后，自动提示用户刷新数据

### 3.3 兼容性需求（明确适配范围，无歧义）

1. 设备兼容性：所有鸿蒙设备（手机、折叠屏、三折屏、平板、鸿蒙 PC）均能正常运行，无布局错乱、功能异常的情况
2. 系统兼容性：适配 HarmonyOS NEXT 5.0 及以上版本，系统版本升级后，应用核心功能不受影响，无需重构核心代码
3. 语言兼容性：三种语言切换后，所有界面文案、数据展示无错乱、无遗漏，符合对应语言的表达习惯

### 3.4 用户体验需求

1. 提示反馈：所有操作（登录、刷新、删除、清理缓存等）均有明确提示，加载中显示加载动画，操作成功 / 失败显示对应提示文案
2. 异常处理：无数据、网络请求失败、验证失败等异常场景，均有专属提示页面，提供明确的解决指引（如 “网络异常，请检查网络连接”“验证失败，请重新验证”）
3. 操作便捷性：核心操作（切换账号、刷新数据、切换语言 / 主题）步骤不超过 2 步，界面布局简洁，无冗余操作，符合鸿蒙原生操作习惯

## 五、术语定义（适配两款工具，消除歧义，统一认知）

1. 米游社账号：用户注册的米哈游官方账号，用于登录米游社 App 及旗下游戏
2. 登录凭证（Cookie）：米游社登录后生成的身份验证信息，用于获取游戏数据，仅本地存储
3. Mock 模式（调试模式）：应用的调试场景，数据来自本地 JSON 文件，不请求真实接口
4. Release 模式（正常模式）：应用的正常使用场景，数据来自米游社真实接口
5. 多账号隔离：多个米游社账号的游戏数据、登录信息完全独立，互不干扰
6. 全设备自适应：应用界面可根据设备屏幕尺寸、形态（折叠 / 展开、横 / 竖屏）自动调整布局，保证正常显示

## 六、范围界定

### 6.1 本次 V1.0 范围（必做）

1. 所有基础适配、核心功能、非功能需求均为 V1.0 必做内容
2. 仅支持原神、星穹铁道、绝区零三款游戏，不扩展其他游戏
3. 仅支持本地数据存储，不支持云端同步、数据上传
4. 仅实现核心数据展示，不实现增值功能（如练度统计、数据导出）

### 6.2 本次 V1.0 范围外（不做）

1. 不支持米游社账号注册、密码找回功能
2. 不支持自动验证，所有验证操作必须用户手动完成
3. 不支持游戏数据修改、作弊等违规功能
4. 不支持云端存储、数据同步、社交分享（V2.0 新增）
5. 不支持其他非米哈游旗下游戏的数据查询
