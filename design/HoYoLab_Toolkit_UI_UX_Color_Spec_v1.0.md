# HoYoLab_Toolkit_UI_UX_Color_Spec_v1.0（UI/UX及颜色设计总规范）

# 一、文档概述

## 1.1 基本信息

- 版本：v1.0

- 适用范围：米游社数据工具箱（HoYoLab Toolkit）全端UI/UX设计、颜色应用及原型开发落地

- 设计理念：轻二次元 + 鸿蒙原生规范 | 纯黑白系统背景 + 内容层独立配色 | 无分割线原生组件

- 核心定位：本文档为**UI/UX及颜色设计总规范**，聚焦视觉基础、配色体系、交互规则等核心设计标准；另需单独编制《HoYoLab_Toolkit_Page_Detail_Spec_v1.0》，用于规范各页面具体细节，两者配合使用，确保设计与开发统一。

- 核心约束：页面背景为纯黑/纯白，内容层与系统背景严格区分，Navigation/TabBar 无分割线；padding、圆角均为2的倍数，字体包含Bold、Medium、Normal三种样式

## 1.2 设计原则

1. 系统背景优先：页面背景（Page Background）严格使用**纯白（#FFFFFF，Light）/纯黑（#000000，Dark）**，不自定义、无渐变

2. 内容层独立：所有内容容器（卡片、导航、TabBar、按钮）使用独立配色，与系统背景形成清晰视觉层级

3. 组件极简：Navigation、TabBar 彻底移除分割线，仅保留内容层背景色与弱阴影区分层级

4. 配色克制：以「米游蓝」为主色，功能色完整保留，无多余装饰色，轻二次元风格

5. 一致性：全端复用统一色值、组件样式，padding、圆角统一为2的倍数，字体样式统一为Bold、Medium、Normal三种，确保视觉与交互统一

# 三、视觉基础规范（新增核心）

## 3.1 视觉底层规则

- 层级区分：以「系统背景-内容层-功能元素」三层结构为核心，系统背景纯黑/纯白，内容层通过背景色、阴影区分，功能元素通过配色、字体样式突出

- 视觉优先级：核心功能（按钮、选中态）> 内容信息（标题、正文）> 辅助信息（说明、占位符），通过配色、字体粗细、间距明确区分

- 风格统一：轻二次元风格仅通过米游蓝主色、浅蓝辅助色点缀，不添加多余二次元元素（如卡通图标、渐变纹理），贴合鸿蒙原生简洁质感

## 3.2 字体基础规范

- 字体选型：全端使用系统默认字体，鸿蒙端优先使用HarmonyOS Sans，确保跨设备显示一致

- 字体样式：仅保留三种样式——Bold（加粗，用于标题、选中态文字）、Medium（中等粗细，用于按钮、操作区文字）、Normal（常规，用于正文、辅助说明），无其他自定义样式

- 字号规范：字号均为2的倍数，可选值为12px、14px、16px、18px、20px，其中标题18-20px（Bold）、正文14-16px（Normal）、辅助说明12px（Normal）

## 3.3 间距与布局规范

- 间距规则：所有组件内边距（padding）、外边距（margin）均为2的倍数，可选值为0、4、8、16、32px，同层级组件间距统一，避免杂乱

- 布局原则：采用flex布局，对齐方式统一（左对齐为主，标题、按钮可居中），组件间距均匀，确保视觉平衡

- 圆角规范：所有组件圆角均为2的倍数，可选值为0、4、8、16、32px，核心组件（按钮、卡片）圆角按规范固定，不自定义

# 五、交互规则规范（新增核心）

## 5.1 通用交互规则

- 反馈原则：所有可交互元素（按钮、链接、TabBar）点击/选中时需有明确反馈，反馈样式遵循配色规范（选中态用米游蓝#0066CC，点击反馈用浅蓝#E6F0FF）

- 操作逻辑：同类型组件交互逻辑统一（如所有按钮点击反馈一致、所有卡片点击效果一致），避免用户混淆

- 禁用状态：禁用元素（按钮、输入框）不可点击，鼠标悬浮无反馈，颜色遵循文本禁用色规范，添加明确禁用视觉提示

## 5.2 核心组件交互规范

- Navigation（导航栏）：标题居中，左侧返回按钮点击返回上一级，右侧操作按钮点击触发对应功能（如设置、搜索），无额外交互效果

- TabBar（底部标签栏）：点击标签切换对应页面，选中态保持米游蓝#0066CC（Bold），未选中态保持系统默认颜色（Normal），切换无过渡动画，确保流畅性

- Card（内容卡片）：点击卡片触发对应详情页，悬浮时无额外效果，仅点击时有浅蓝背景反馈，卡片内按钮交互遵循Button组件规范

- Button（按钮）：主按钮/辅助按钮点击时背景色轻微加深（主按钮#0055BB，辅助按钮边框#0055BB），松开后恢复原样式；禁用按钮点击无任何反馈

## 5.3 页面交互规范

- 页面切换：所有页面切换无过渡动画，直接跳转，确保操作流畅，不添加多余视觉干扰

- 明暗模式切换：切换按钮点击后，页面背景、内容层配色、文本色同步切换，无延迟、无异常错位

- 滚动交互：页面滚动时，Navigation栏固定在顶部，TabBar固定在底部，内容层滚动无卡顿，滚动到顶部/底部时无回弹效果

# 六、适配与技术约束（新增核心）

## 6.1 全端适配要求

- 设备适配：支持鸿蒙手机端（主流尺寸：1080x2400、1200x2700）、平板端（主流尺寸：1200x1920），适配原则为“内容自适应，组件比例不变”

- 屏幕适配：适配不同屏幕比例，内容层居中显示，左右留白均匀，不出现内容截断、拉伸现象

- 字体适配：字号随屏幕尺寸自适应调整（按2的倍数缩放），确保不同设备上可读性一致，字体样式保持不变

## 6.2 技术落地约束

- 色值约束：所有前端实现需严格使用规范中定义的色值（十六进制、RGB均需匹配），禁止自行调整色值亮度、饱和度

- 组件约束：Navigation、TabBar 必须移除分割线，仅通过弱阴影区分层级，阴影参数严格遵循规范，不自定义

- 间距约束：padding、圆角必须为2的倍数，前端实现时需严格按规范取值，无自定义非2倍数间距、圆角

- 兼容性约束：适配鸿蒙4.0及以上版本，确保组件样式、交互效果在不同版本中一致，无兼容性异常

## 6.3 开发注意事项

- 原型与开发一致性：开发需严格对照本总规范、页面细节规范及AI生成的原型，确保视觉样式、交互逻辑完全一致，无偏差

- 性能约束：页面加载速度≤1.5s，切换页面无卡顿，明暗模式切换无延迟，避免因样式复杂导致性能下降

- 可维护性：代码需按规范命名，配色、组件样式统一提取为公共样式，便于后续版本迭代、修改

# 七、核心组件规范（无分割线）

## 7.1 通用规范补充

- padding规范：所有组件padding值均为2的倍数，可选值为0、4、8、16、32px，无其他自定义padding值

- 圆角规范：所有组件圆角均为2的倍数，可选值为0、4、8、16、32px，无其他自定义圆角值

- 字体规范：使用系统默认字体，统一包含三种样式——Bold（加粗）、Medium（中等粗细）、Normal（常规），无其他字体样式

## 7.2 Navigation（导航栏）

- 核心要求：无分割线，仅用弱阴影区分层级

- 背景：内容层主背景（#FFFFFF / #000000）

- 标题/操作区颜色：#0066CC（符合配色规范）；标题字体样式为Bold，操作区字体样式为Medium

- padding：遵循通用规范（2的倍数），其余细节（图标大小、高度等）：遵循系统默认配置，不额外定义

## 7.3 TabBar（底部标签栏）

- 核心要求：无分割线，仅用弱阴影区分层级

- 背景：内容层主背景（#FFFFFF / #000000）

- 选中态：颜色遵循配色规范（#0066CC），字体样式为Bold

- 未选中态：颜色遵循系统默认配置，不额外定义；字体样式为Normal；其余细节（图标大小、高度、布局等）遵循系统默认配置，不额外定义；padding、圆角遵循通用规范（2的倍数）

## 7.4 Card（内容卡片）

- 圆角：12px（2的倍数，符合通用规范）

- 背景：内容层次要背景（#F0F2F5 / #262626）

- 内边距：16px（2的倍数，符合通用规范）

- 阴影：0 1px 2px rgba(0,0,0,0.05)（Light）/ 0 1px 2px rgba(255,255,255,0.05)（Dark）

- 字体样式：卡片标题为Bold，正文为Normal，辅助说明为Normal

## 7.5 Button（按钮）

- 主按钮：高度44px，圆角8px（2的倍数），背景#0066CC，文字白色16px，字体样式为Medium；内边距遵循通用规范（2的倍数）

- 辅助按钮：背景透明，边框#0066CC，文字#0066CC，字体样式为Medium；圆角8px（2的倍数），内边距遵循通用规范（2的倍数）

- 禁用状态：字体样式为Normal，颜色遵循文本禁用色规范
