# 米游社数据工具箱（纯血鸿蒙版）

# 页面细节规范

## 文档版本：V1.0

## 文档类型：UI/交互实现（长什么样、怎么交互）

## 适用对象：开发、Kiro、Trae CN

## 文档说明

- 文档版本：V1.0
- 适配工具：Kiro AI IDE、Trae CN（字节系）
- 核心适配：鸿蒙全设备（手机竖屏 / 折叠屏 / 双折 / 三折 / 平板 / 鸿蒙 PC）
- 文档用途：供 AI 工具识别、开发人员落地，包含所有确认的页面细节、交互逻辑、业务规则，无冗余、无模糊，完全对齐需求共识
- 核心原则：遵循鸿蒙官方响应式布局，三套游戏角色详情独立设计，防暴力点击、合规性要求全覆盖，符合 Kiro 规范驱动开发与 Trae CN 深度上下文理解的核心需求

## 一、全局通用规则（所有页面适用）

### 1. 鸿蒙全设备自适应规范

- 布局基础：采用鸿蒙官方响应式布局体系，使用 Row/Column/Flex 弹性布局，不写死像素宽度，采用 Weight/Percentage 适配，结合 Breakpoint 断点实现全设备自适应
- 导航适配：Navigation 组件自动适配，手机竖屏标题居中，折叠屏 / 平板 / PC 标题左对齐；BottomTabBar 在手机竖屏显示（图标 + 文字），折叠屏 / 平板 / PC 自动转为左侧侧边栏导航，双折 / 三折屏根据形态自动切换
- 内容适配：列表、卡片、网格根据屏幕宽度自动调整列数（手机单列 / 双列，平板 / PC 多列），文字、间距自动适配屏幕尺寸，不拉伸、不变形
- 主题适配：浅色 / 深色模式跟随系统，全设备保持一致，LaunchPage、所有页面背景自动适配主题
- 交互统一：所有页面交互逻辑、业务流程全设备统一，仅布局自适应调整，降低开发与 AI 识别成本

### 2. 刷新规则（全局统一）

- 刷新触发：下拉刷新、页面右上角刷新按钮
- 冷却限制：两次刷新时间间隔＜30 分钟，弹出 Dialog 弹窗提示：“刷新过于频繁可能会触发米游社人机验证，确定要继续刷新吗？”，弹窗含 “取消”“继续刷新” 两个按钮
- 刷新逻辑：刷新时按钮置灰禁用，直到刷新结果返回（成功 / 失败），恢复按钮可点击状态
- 数据处理：刷新成功后更新本地数据库，同步刷新页面；刷新失败弹出 Toast 提示失败原因

### 3. 防暴力点击规则（所有可点击按钮适用）

- 核心原则：所有按钮点击后立即置灰禁用，等待接口返回 / 动作完成后，再恢复可点击状态，避免连续暴力点击
- 覆盖按钮：获取验证码、登录、刷新二维码、保存 Cookie、协议确认、删除账号、清理缓存等所有可交互按钮
- 特殊限制：获取验证码按钮额外增加 60 秒倒计时（手机号格式合法才可点击），倒计时期间不可再次点击

### 4. 空状态 / 异常状态通用规范

- 空状态：无数据时，居中展示占位图标 + 提示文字 + 操作按钮（如有），样式统一，与对应页面风格适配
- 异常状态：网络失败、验证失败、数据加载失败时，展示对应提示文案 + 刷新按钮，引导用户重新操作
- 加载状态：所有数据加载、接口请求时，展示加载动画，不显示空白页面

### 5. 合规要求

- 用户协议与隐私政策：登录页底部固定展示，包含 “登录即表示您同意《用户协议》与《隐私政策》”，协议文字可点击，点击后打开内置网页展示协议内容，不影响登录操作（适配应用市场审核要求）
- 数据安全：所有登录凭证、游戏数据、账号信息仅本地加密存储，不上传至任何第三方服务器，不获取无关设备权限

## 二、页面详细规范（按页面流程排序）

### 1. 启动页（Launch Page）

#### 页面基础

- 页面名称：LaunchPage
- 页面作用：应用启动纯视觉展示，无任何业务逻辑
- 跳转规则：固定展示 500ms~800ms 后，强制直接进入 MainPage，不可跳过、不可点击，不判断任何账号状态

#### 布局与样式

- 背景：纯色背景，自动适配浅色 / 深色模式（浅色白底 + 深色 Logo，深色黑底 + 白色 Logo），无渐变、无复杂效果
- 中央元素：居中展示 App 圆角 Logo，Logo 下方可选择展示 App 名称（标准字号，简洁清晰）
- 动画效果：轻微淡入（0.3 秒，从透明到完全显示）+ 轻微缩放（从 0.9 倍放大至 1.0 倍），无抖动、无旋转、无复杂动效

### 2. 主页面（Main Page）

#### 页面基础

- 页面名称：MainPage
- 页面结构：底部 TabBar + 顶部 NavigationBar，TabBar 固定 3 个选项，切换时仅替换内容区，不重新创建页面实例
- 默认选中：Tab1（战绩页）

#### 底部 TabBar（3 个选项，按顺序）

1. Tab1：战绩（图标 + 文字，默认选中）
2. Tab2：角色列表（图标 + 文字）
3. Tab3：我的（图标 + 文字）

#### 各 Tab 页面通用结构

- 每个 Tab 页面独立携带自身 NavigationBar，显示对应页面标题，右侧可根据页面需求添加刷新、设置等按钮
- 内容区采用纵向滚动布局，适配全设备自适应规则

### 3. Tab1：战绩页（IndexHomePage）

#### 页面基础

- 页面名称：IndexHomePage
- Navigation 标题：战绩
- 进入逻辑：进入页面优先判断本地是否有已添加的米游社账号，分两种状态展示

### 状态 1：无账号（Placeholder 页面）

#### 布局：居中布局，与角色列表页空状态样式统一

- 内容：
  - 顶部：占位图标（empty_box / 账号类图标）
  - 中部：提示文字 “暂无添加任何米游社账号，请先添加账号”
  - 底部：“添加账号” 按钮，点击后跳转至登录页（LoginPage）

#### 状态 2：有账号（战绩列表展示）

- 布局：按米游社账号分组展示，采用 List+Group 分组布局，支持全设备自适应列数
- 分组规则：
  - 每组顶部：Section Header（账号标题栏），显示账号昵称、米游社 ID
  - 每组内部：该账号下所有游戏的战绩卡片，默认全部展开
  - 交互：点击 Section Header，切换分组展开 / 折叠状态（折叠后仅显示 Header，隐藏游戏卡片）

#### 游戏战绩卡片内容（按游戏区分，统一卡片样式）

- 通用内容：游戏图标、游戏昵称、游戏 UID
- 原神卡片：原粹树脂（当前 / 封顶）、回满时间、洞天财瓮（当前 / 封顶）、每日委托完成状态、值得铭记的强敌剩余次数、参量质变仪状态、探索派遣状态
- 星穹铁道卡片：开拓力（当前 / 封顶）、回满时间、后备开拓力（当前值）、每日实训（当前 / 封顶）、历战余响（当前 / 封顶）、模拟宇宙积分（当前 / 封顶）、货币战争积分（当前 / 封顶）
- 绝区零卡片：电量（当前 / 封顶）、回满时间、周期任务（当前 / 封顶）、收入一览

#### 交互规则

- 点击单个游戏战绩卡片：跳转至该游戏的实时便笺页（RealTimeNotePage）
- 下拉刷新：触发全局刷新规则，更新所有账号的所有游戏战绩数据
- 右上角按钮：设置（跳转至设置页）、账号切换（跳转至账号列表页）

### Tab2：角色列表页（CharacterListPage）

#### 页面基础

- 页面名称：CharacterListPage
- Navigation 标题：角色列表
- 进入逻辑：与战绩页完全一致，优先判断本地是否有已添加的米游社账号，无账号展示同款 Placeholder 页面（图标 + 提示语 + 添加账号按钮）

#### 有账号状态：页面结构

- 顶部：双筛选器（上下排列，手机竖屏；左右排列，折叠屏 / 平板 / PC）
  1. 筛选器 1：账号选择（下拉选择器，默认选中第一个账号），显示账号昵称
  2. 筛选器 2：游戏选择（下拉选择器，默认选中原神），选项：原神 / 星穹铁道 / 绝区零

* 内容区：角色列表，仅显示 “当前选中账号 × 当前选中游戏” 的角色，无其他账号 / 游戏角色混排

#### 角色列表展示规则

- 布局：手机竖屏显示单列 / 双列网格，折叠屏 / 平板 / PC 显示多列网格（自动适配）
- 单角色卡片内容：角色头像、角色名称、角色星级、角色等级、武器 / 光锥简要信息（名称 + 精炼 / 叠影等级）
- 特殊状态：当前账号无该游戏角色时，展示提示文字 “当前账号未查询到【XXX】角色数据，请下拉刷新”

#### 交互规则

- 筛选器切换：切换账号 / 游戏后，实时刷新角色列表，仅显示对应角色
- 下拉刷新：仅刷新当前选中账号 × 当前选中游戏的角色数据，遵循全局刷新规则
- 点击角色卡片：跳转至该角色的详情页（CharacterDetailPage）
- 右上角按钮：刷新（刷新当前角色列表）、账号切换（跳转至账号列表页）

### Tab3：我的页（ProfilePage）

#### 页面基础

- 页面名称：ProfilePage
- Navigation 标题：我的
- 布局：纵向列表布局，分 3 个 Section，全设备自适应（手机单列，平板 / PC 可分组并排）

### Section 1：账号管理

- 布局：横向行样式，左侧头像，右侧文字信息
- 内容：已添加账号头像 + 账号昵称 + 米游社 ID + 角色总数（该账号下所有游戏角色合计）
- 交互：点击该行，跳转至账号详情页（AccountDetailPage）

### Section 2：全局设置

- 布局：纵向两行，分别对应主题切换、语言切换
- 第一行：主题切换
  - 显示内容：当前选中主题（跟随系统 / 浅色 / 深色）
  - 交互：点击后弹出选择器，切换主题，实时生效，无需重启应用
- 第二行：语言切换
  - 显示内容：当前选中语言（简体中文 / 繁体中文 / English）
  - 交互：点击后弹出选择器，切换语言，实时生效，无需重启应用

### Section 3：关于

- 布局：横向行样式，左侧文字，右侧版本号
- 内容：左侧 “版本号”，右侧固定显示 “V1.0.0”（后续迭代自增）
- 交互：仅展示，不可点击

## 二级页面：实时便笺页（RealTimeNotePage）

#### 页面基础

- 页面名称：RealTimeNotePage
- 进入方式：战绩页点击单个游戏战绩卡片进入
- 页面逻辑：进入后自动识别游戏类型，仅渲染对应游戏的专属便笺内容，不显示其他游戏模块
- Navigation 标题：实时便笺
- 右上角：刷新按钮（仅刷新当前游戏的便笺数据，遵循全局刷新规则）

### 原神实时便笺（专属内容）

1. 魔神任务：当前魔神任务进度（文案展示）
2. 原粹树脂：图标 + 当前树脂 / 最大树脂 + 回满时间（xx 小时 xx 分钟） + 进度条
3. 洞天财瓮 - 洞天宝钱：当前宝钱 / 最大存储 + 预计存储满时间
4. 每日委托奖励：委托任务（已完成 x / 总 x） + 历练点进度 + 领取状态 + 长效历练点
5. 值得铭记的强敌：提示语 “本周剩余消耗减半次数” + 当前值 / 封顶值
6. 参量质变仪：状态（可使用 / 冷却中），冷却中显示剩余时间（天 时 分）
7. 探索派遣：总派遣人数 / 最大派遣人数 + 角色头像列表 + 每个角色剩余探索时间

### 星穹铁道实时便笺（专属内容）

1. 开拓力：图标 + 当前开拓力 / 上限 + 回满时间
2. 后备开拓力：图标 + 当前值
3. 每日实训：当前值 / 上限
4. 历战余响：本周剩余次数 / 上限
5. 模拟宇宙积分：当前值 / 上限
6. 货币战争积分：当前值 / 上限

### 绝区零实时便笺（专属内容）

1. 电量（体力）：图标 + 当前电量 / 上限 + 回满时间
2. 周期任务：当前进度 / 总进度
3. 收入一览：各类货币 / 道具今日获取情况（文案 / 进度条展示）

### 适配规则

1. 布局：纵向列表，每个模块为独立卡片，全设备自适应（手机单列，平板 / PC 多列）
2. 无数据状态：展示空状态占位 + 刷新按钮，提示 “暂无该游戏便笺数据，请刷新重试”

## 二级页面：角色详情页（分三款游戏，独立结构）

## 通用基础规则

- 页面名称：CharacterDetailPage（原神 / 星穹 / 绝区零分别独立，后缀区分）
- 进入方式：角色列表页点击角色卡片进入
- Navigation 标题：角色详情
- 右上角：刷新按钮（仅刷新当前角色数据，遵循全局刷新规则）
- 布局：纵向滚动列表，全设备自适应，三款游戏结构完全独立，不共用布局、不混用内容

## 7.1 原神角色详情页（独立结构）

1. 顶部头部区域

- 角色立绘（原神专属，宽屏展示全身立绘，轻微渐变背景）
- 命座展示：横向排列 1~6 个命座图标，已解锁：正常颜色 + 对应图标；未解锁：置灰 + 叠加锁图标（6 个位置全部显示，不空白）

2. 天赋区域

- 横向展示 3 个核心天赋，每个天赋包含：天赋图标 + 天赋名称 + 天赋等级（数字）
- 天赋类型：普通攻击、元素战技、元素爆发

3. 武器区域

- 内容：武器图标 + 武器名称 + 武器等级（Lv.XX） + 精炼等级（精炼 1~5） + 主词条名称 + 主词条数值（如：暴击率：22.1%）

4. 角色属性面板

- 列表形式展示，格式：属性名称 + 数值，包含：
- 基础属性：生命值、攻击力、防御力
- 核心属性：暴击率、暴击伤害、元素精通、充能效率、元素伤害加成

5. 圣遗物区域（5 个固定部位）

- 部位：花、羽、沙、杯、头，每个部位独立卡片
- 有圣遗物：圣遗物图标 + 圣遗物名称 + 等级（+0~+20） + 主词条名称 + 数值 + 副词条列表（每条：名称 + 数值）
- 无圣遗物：对应部位占位图标 + 提示文字 “该部位未装备圣遗物”

## 7.3 绝区零角色详情页（独立结构）

1. 顶部头部区域

- 角色立绘（绝区零专属，宽屏展示）
- 进阶 / 命座展示：绝区零专属样式，横向排列对应进阶图标，已解锁正常显示，未解锁置灰 + 锁图标

2. 技能区域

- 横向 / 纵向展示 4 个核心技能，每个技能包含：图标 + 技能名称 + 等级（数字）
- 技能类型：普通攻击、特殊攻击、终结技、闪避 / 特殊机制

3. 装备区域

- 内容：驱动盘 / 武器装备图标 + 装备名称 + 等级 + 精炼等级 + 主属性名称 + 主属性数值

## 8. 登录页（添加账号页，LoginPage）

### 页面基础

- 页面名称：LoginPage
- 进入方式：
  1. 战绩 / 角色列表页空状态 → 点击 “添加账号”
  2. 我的页 → 账号管理 → 新增账号
- 页面结构：上中下三段（顶部品牌区、中间登录方式切换区、底部协议区）

### 顶部品牌区

- 布局：居中展示，简洁清晰
- 内容：App 圆角图标（居中） + App 名称（图标下方，标准字号），无复杂动画

### 中间登录方式切换区

- 切换方式：分段选择器 / Tab 切换，3 种方式互斥，同一时间仅显示一种方式内容
- 方式 1：手机号登录
  - 表单：11 位手机号输入框 + 短信验证码输入框
  - 按钮：获取验证码、登录
  - 规则：
    - 手机号未输入 / 格式不合法 → 获取验证码按钮置灰不可点击
    - 点击获取验证码 → 置灰 + 60 秒倒计时，倒计时期间不可点击
    - 手机号 / 验证码为空 → 登录按钮置灰不可点击
    - 点击登录 → 置灰禁用，直到登录结果返回
- 方式 2：扫码登录
  - 内容：米游社登录二维码（居中） + 提示文字 “请使用米游社 App 扫码授权”
  - 按钮：刷新二维码
  - 规则：点击刷新二维码 → 置灰禁用 3 秒，防止连续点击，同时重新请求二维码
- 方式 3：手动填写 Cookie
  - 表单：多行 / 单行输入框（提示 “请粘贴米游社登录 Cookie”）
  - 按钮：保存并校验 Cookie
- 规则：
  - Cookie 输入框为空 → 保存按钮置灰不可点击
  - 点击保存 → 置灰禁用，直到校验完成，校验成功 / 失败后恢复按钮

### 底部协议区

- 布局：页面最底部，居中展示
- 内容：“登录即表示您同意《用户协议》与《隐私政策》”，其中《用户协议》《隐私政策》为可点击文字
- 交互：点击协议文字 → 打开内置网页，展示对应协议内容

### 登录结果处理

- 登录成功：保存账号信息到本地数据库，自动返回 MainPage→战绩页，并自动拉取该账号游戏数据
- 登录失败：弹出 Toast/Dialog 提示失败原因，恢复按钮可点击状态

## 9. 全局弹窗规范（所有弹窗统一）

### 1. 刷新冷却 Dialog

- 触发场景：两次刷新时间间隔＜30 分钟
- 内容：标题 “提示”，提示文案 “刷新过于频繁可能会触发米游社人机验证，确定要继续刷新吗？”
- 按钮：取消（左）、继续刷新（右）
- 交互：点击继续刷新 → 执行刷新；点击取消 → 终止刷新

### 2. 人机验证弹窗

- 触发场景：登录、刷新数据时触发米游社风控验证
- 内容：内嵌极验 Geetest v4 验证网页，无自定义验证 UI
- 交互：用户手动完成验证（滑块 / 点选等）→ 验证通过，继续执行原操作；验证失败，提示 “验证失败，请重新验证”，可取消验证（终止原操作）

### 3. 确认弹窗（删除账号 / 清理缓存）

- 触发场景：删除账号、清理缓存时
- 内容：标题 “确认”，提示文案（删除账号：“删除后该账号所有本地数据将被清除，不可恢复，确定要删除吗？”；清理缓存：“确定要清理本地缓存吗？清理后将释放存储空间”）
- 按钮：取消（左）、确认（右）
- 交互：点击确认 → 执行对应操作；点击取消 → 终止操作

## 四、术语定义（适配 Kiro/Trae CN，消除歧义）

- 米游社账号：用户注册的米哈游官方账号，用于登录米游社 App 及旗下游戏
- 登录凭证（Cookie）：米游社登录后生成的身份验证信息，仅本地加密存储，用于获取游戏数据
- Mock 模式（调试模式）：应用调试场景，数据来自本地预设 JSON 文件，不请求真实接口，与 Release 模式展示逻辑一致
- Release 模式（正常模式）：应用正常使用场景，数据来自米游社真实接口
- 多账号隔离：多个米游社账号的游戏数据、登录信息完全独立，互不干扰
- 鸿蒙响应式布局：基于鸿蒙官方组件，一套代码适配所有鸿蒙设备，自动调整布局、列数、间距
- 防暴力点击：按钮点击后立即置灰禁用，避免连续点击导致的接口异常或风控触发
