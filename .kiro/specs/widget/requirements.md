# Widget 多账号混合显示 - 需求文档

## 背景

当前 Widget 实现只支持单账号单游戏或单账号多游戏的显示方式，无法实现多账号混合显示的需求。

## 目标

支持多账号、多游戏的灵活组合显示：
- 同一 Widget 可以显示不同账号的同款游戏数据
- 例如：2×2 Widget 同时显示 A 账号原神 + B 账号原神的体力信息
- 用户可以自由配置每个 Widget 显示哪些账号的哪些游戏

## 核心需求

### 1. 数据存储结构

App 需要存储所有账号的所有游戏 Widget 数据，形成一个全局数据池，供各 Widget 读取。

**数据结构要求**：
- 支持多账号
- 每个账号下支持多游戏
- 每个游戏包含完整的体力数据和额外数据
- 数据结构易于扩展和解析

### 2. Widget 配置结构

每个 Widget 需要记录用户选择的显示组合（slots）：

**配置要求**：
- 记录 Widget 尺寸
- 记录该 Widget 显示的账号+游戏组合列表
- 组合顺序决定显示顺序

### 3. 显示规则

| Widget 尺寸 | 最大 slots 数量 | 布局说明 |
|------------|----------------|---------|
| 1×2 | 1 | 单行显示：游戏名 + UID + 体力 |
| 2×2 | 2 | 两行显示：每行一个 slot |
| 2×4 | 2 | 两行显示（更宽） |
| 4×4 | 3 | 三行显示 |

### 4. 用户配置流程

1. 用户选择 Widget 尺寸
2. 用户选择要显示的账号+游戏组合（可跨账号）
3. 系统保存配置并渲染预览
4. 用户确认后添加到桌面

## 用户场景

### 场景 1：单账号单游戏

用户 A 有一个原神账号，添加 2×2 Widget 只显示自己的原神体力。

### 场景 2：单账号多游戏

用户 A 有原神和星铁账号，添加 4×4 Widget 同时显示两款游戏的体力。

### 场景 3：多账号同游戏（新增支持）

用户 A 和用户 B 都有原神账号，添加 2×2 Widget 同时显示两个账号的原神体力：
- 第一行：A 账号原神（140/200）
- 第二行：B 账号原神（80/200）

### 场景 4：多账号多游戏混合

用户 A 有原神和星铁，用户 B 有原神，添加 4×4 Widget 显示：
- 第一行：A 账号原神
- 第二行：A 账号星铁
- 第三行：B 账号原神

## 约束

1. Widget 数据由 App 进程写入，FormExtensionAbility 进程读取
2. 数据通过 LocalStorage 传递给 Widget 组件
3. Widget 刷新由系统控制，最短 5 分钟
4. 配置信息需要持久化存储（关联 formId）
