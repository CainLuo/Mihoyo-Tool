# 需求文档：持久化同步队列

## 背景

当用户登录账号或手动触发同步时，App 需要向米游社 API 发起多个请求（角色列表、角色详情等）。由于网络波动或用户主动杀掉 App，正在进行的请求可能中断，且下次打开 App 后不会自动重试，导致数据不完整。

## 需求

### 1. 持久化同步队列

**用户故事**：作为用户，我希望即使在同步过程中关闭 App，下次打开时也能自动继续未完成的同步，不需要手动重新触发。

**验收标准**：

- 所有需要同步的任务在执行前必须先写入 DB（`sync_meta` 表，`syncStatus='pending'`）
- App 启动时，自动检查并恢复所有 `pending` 状态的任务
- 每个任务执行前标记为 `syncing`，成功后标记为 `success`，失败标记为 `failed`
- 单个任务失败不影响其他任务的执行

### 2. 登录后自动同步

**用户故事**：作为用户，我希望登录账号后，App 自动在后台同步所有游戏的角色数据，不需要手动触发。

**验收标准**：

- 登录成功后，自动把以下任务加入队列并执行：
  - 原神：角色列表（`genshin_character_list`）+ 角色详情（`genshin_character_detail`）
  - 星铁：角色列表（`starrail_avatar_basic`）+ 角色详情（`starrail_avatar_info`）
  - 绝区零：角色列表（`zzz_avatar_basic`）+ 角色详情（`zzz_avatar_info`）
- 同步在后台进行，不阻塞登录流程

### 3. 手动刷新同步

**用户故事**：作为用户，我希望在角色页点击刷新时，也能触发持久化同步，防止中途被杀 App。

**验收标准**：

- Characters 页手动刷新时，同样通过持久化队列执行同步
- 刷新逻辑与登录后自动同步使用相同的队列机制

### 4. 绝区零角色详情逐个同步

**用户故事**：作为用户，我希望绝区零的角色详情能完整同步，即使 API 不支持批量获取。

**验收标准**：

- mock 环境：一次请求返回所有角色详情（`event_game_record_zzz_api_zzz_avatar_info.json`）
- 真实环境：遍历 `avatar_basic` 里的每个角色 id，逐个请求详情
- 每个角色的同步任务独立记录，成功一个删一个（通过 `syncStatus` 标记）

### 5. 原神角色详情同步

**用户故事**：作为用户，我希望点击原神角色卡片时能看到完整的角色详情（武器、圣遗物、技能、命座）。

**验收标准**：

- 登录后自动同步原神角色详情（`character_detail_all` 接口）
- `GenshinRepository.parseCharacterDetail` 直接存原始 API 数据，不做 UI 转换
- `GenshinCharacterDetailViewModel` 负责把原始数据转换为 UI 展示格式
